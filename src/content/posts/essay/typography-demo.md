这篇文章有两个用途：一是让你直观看到 `typography: kai` 的实际效果，二是把这项功能的用法和背后的取舍记录清楚。如果你只是想看效果，往下滚动即可；如果你想知道怎么切换、怎么关掉，直接跳到最后一节。

正文使用的是仓耳今楷 02。楷体的笔画比黑体更接近手写，字面也更小，所以在同样的字号下会显得稀疏。为了让阅读节奏不至于散掉，这个预设把字号从 16px 提到 17px，行高放到 1.9，并加了 0.02em 的字距。这些数值不是随手写的，是在长段落里反复比对后定下的——太小会挤，太大会散。

首行缩进取 2 个字符宽度，也就是 `text-indent: 2em`。中文排版里这是最自然的段落分界方式，比段间空行更省纵向空间，也更接近纸质书的阅读经验。

## 段落、引用与列表

下面这段用来检查段间距。缩进式排版通常不需要很大的段距，所以这里把上下间距从默认的 1.25em 压到 0.55em，让视线沿着缩进形成的"锯齿"往下走，而不是被空白打断。

> 引用块不做首行缩进。它已经有左边框作为视觉分隔，再缩进反而会破坏对齐关系。

列表同样不缩进，因为列表项自身的标记已经承担了缩进职能：

- 无序列表项不缩进
- 列表里的第二行折行后与首行对齐
- 如果列表项里嵌套了段落，那些段落也不缩进

## 表格与代码

表格的单元格不缩进，表头回退到无衬线的 Rubik——楷体只有 400 一个字重，标题和表头如果强行加粗，浏览器会用合成粗体，边缘会发毛。

| 预设             | 字体        | 额外请求                 |
| ---------------- | ----------- | ------------------------ |
| 省略或 `default` | Rubik       | 无                       |
| `kai`            | 仓耳今楷 02 | 字体声明与用到的字形分片 |
| `serif`          | 系统宋体    | 无                       |

行内代码如 `text-indent: 2em` 会保持等宽字体，不跟随正文变成楷体。代码块同理：

```css
.app-prose[data-typography="kai"] p {
  text-indent: 2em;
  margin-block: 0.55em;
}
```

:::note
Callout 内的段落也不缩进。这类块级提示本身就是一个独立的视觉单元，缩进会让它和正文的层级关系变得模糊。
:::

## 关于字体加载

仓耳今楷的字形文件按 `unicode-range` 拆成了 97 个分片，托管在阿里云 CDN 上。浏览器只会下载页面实际用到的字符所覆盖的分片，没用到的不会碰。这也是为什么这篇只有一千多字的文章，不会把整套字体拖下来。

代价是这个预设只对个别文章开启比较划算。如果全站都用，首次访问的字体下载量会明显高于现在的 Rubik。所以默认值保持原样，需要时再在 frontmatter 里写一行。

## 怎么切换或关掉

在文章 frontmatter 里加一行即可：

```yaml
typography: kai
```

改成 `serif` 会换成系统宋体栈，不产生任何字体请求；删掉这一行、或者写成 `default`，就回到全站现状——Rubik 无衬线、无首行缩进，页面上连一个多余属性都不会输出。

字体分片声明在 `public/fonts/jinkai.css`，预设规则在 `src/styles/post-typography.css`，枚举与映射在 `src/types/typography.ts`。要加新预设，改这三处就够了。
